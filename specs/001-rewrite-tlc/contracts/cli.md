# CLI Contract — Native TLC Command Line Tool

## Command: `tlc run`
- **Synopsis**
  ```bash
  tlc run --spec <path> --config <path> [--workers <n>|auto] [--memory-limit <bytes>]
          [--progress tty|ndjson] [--telemetry local|json|otlp]
          [--param KEY=VALUE ...] [--checkpoint-dir <path>]
  ```
- **Purpose**: Execute a model check from scratch using the provided modules and configuration.
- **Required Arguments**
  - `--spec`: Path to primary TLA+ module.
  - `--config`: Path to configuration (`MC.cfg`) file.
- **Optional Arguments**
  - `--workers`: Override worker count. `auto` resolves to `max(logical cores − 1, 1)`.
  - `--memory-limit`: Upper bound on in-memory state cache (bytes, accepts `_GiB` suffix).
  - `--progress`: Controls output mode. `tty` renders progress bar via `indicatif`; `ndjson` emits newline-delimited JSON events.
  - `--telemetry`: Selects telemetry sink. `local` writes JSON spans to `logs/tlc-trace.json`; `json` mirrors spans to stdout; `otlp` streams to OTLP collector (requires `--otlp-endpoint`).
  - `--param`: Repeated key-value overrides for spec parameters.
  - `--checkpoint-dir`: Directory for checkpoint blobs (default `checkpoints/<run-id>`).
- **Behavior**
  - Emits run metadata (ULID run ID, spec hash) at start.
  - Writes checkpoints according to resume policy (default enabled).
  - Returns exit status aligned with legacy TLC (0 success, 2 violation, etc.).

## Command: `tlc resume`
- **Synopsis**
  ```bash
  tlc resume --checkpoint <path> [--progress tty|ndjson] [--workers <n>|auto]
             [--telemetry local|json|otlp] [--ignore-hash]
  ```
- **Purpose**: Restart exploration from a persisted checkpoint.
- **Required Arguments**
  - `--checkpoint`: Path to `.chk` manifest generated by `tlc run`.
- **Optional Arguments**
  - `--workers`, `--progress`, `--telemetry`: Same semantics as `tlc run`.
  - `--ignore-hash`: Bypass spec hash mismatch guard (debug only; logs warning).
- **Behavior**
  - Validates checkpoint integrity (`spec_hash`, chunk digests).
  - Restores frontier/backlog, visited set, RNG seeds, and telemetry context.
  - Produces new `run-id`; appends resume lineage to run logs.

## Command: `tlc checkpoint list`
- **Synopsis**
  ```bash
  tlc checkpoint list --run-id <ulid> [--output json|table]
  ```
- **Purpose**: Enumerate checkpoints associated with a run.
- **Arguments**
  - `--run-id`: ULID reported by `tlc run` / `tlc resume`.
  - `--output`: Defaults to `table`; `json` dumps machine-readable manifest.
- **Behavior**
  - Displays checkpoint IDs, creation timestamps, sizes, and spec hash.

## Command: `tlc checkpoint inspect`
- **Synopsis**
  ```bash
  tlc checkpoint inspect --checkpoint <path> [--details frontier|visited|metrics]
  ```
- **Purpose**: Inspect metadata for a specific checkpoint.
- **Arguments**
  - `--checkpoint`: Path to checkpoint manifest.
  - `--details`: Optional focus area; `frontier` enumerates chunk stats, `visited` summarizes fingerprint counts, `metrics` prints runtime metrics snapshot.

## Command: `tlc parity`
- **Synopsis**
  ```bash
  tlc parity --legacy <path> --specs <dir> [--filter <glob>] [--output <dir>]
             [--workers <n>] [--golden-cache <dir>]
  ```
- **Purpose**: Run the golden parity harness, executing specs against both Rust and legacy TLC.
- **Arguments**
  - `--legacy`: Path to legacy TLC launcher (`tlc.sh` or `java -cp ...`).
  - `--specs`: Directory containing regression suite specs.
  - `--filter`: Glob to narrow suite (e.g., `Paxos*`).
  - `--output`: Directory for diff reports (default `artifacts/parity`).
  - `--workers`: Worker count for Rust TLC when running parity.
  - `--golden-cache`: Directory storing legacy outputs to reuse across runs.
- **Behavior**
  - Executes each spec sequentially (or batched), capturing outputs from both binaries.
  - Produces structured parity report summarizing status (`Match`, `Mismatch`, `Inconclusive`) plus metrics deltas.
  - Non-zero exit when mismatches detected.

## Progress Event Schema (NDJSON Mode)
- Each line is a JSON object matching:
  ```json
  {
    "event_id": "01HZYF3V7P8Z3M7YKB8N0YJQBJ",
    "run_id": "01HZYF3V5VZ2SXDF5C7TE0YE8N",
    "timestamp": "2025-11-02T03:25:45.123Z",
    "states_explored": "18446744073709551616",
    "percent_complete": 62.5,
    "throughput_eps": 125000.0,
    "workers_active": 15,
    "eta_seconds": 5400
  }
  ```
- `states_explored` and `run_id` use string encoding to preserve precision.
- Absent `eta_seconds` indicates unknown ETA.

## Exit Codes
- `0`: Successful completion, invariants satisfied.
- `1`: CLI usage error (invalid args, missing files).
- `2`: Safety/liveness violation detected (counterexample produced).
- `3`: Resource exhaustion (memory, disk).
- `4`: Telemetry/export failure (non-fatal to run state but flagged).
- `130`: User-interrupted (propagated signal).

## Compatibility Notes
- Command set supersedes legacy TLC flags; legacy aliases retained via hidden `clap` attributes.
- JSON/TTY outputs stable across minor releases; breaking changes require major version bump or feature flag.
- No RPC/HTTP server is exposed; orchestration occurs via CLI invocation directly or through container entrypoints.
